这 3,849 个源成员全部映射到 3,847 个学习词形。拼写核查使用的官方词典页面仅用于核对词头，未复制其释义或音标。没有自动词干化，也没有通过去标点把所有不同词形混为一谈。该有限清理不等同于逐项义项校对。

## 通用义、计算机候选义与场景义分开

`wordPresentation(word)` 返回全新的 `{badges, meanings, tags, sources}`：

1. 对原始 224 个稳定 ID 且词形相符的词条，先展示“本场景义 · 原创例句”。`technical-context` 表示有该项目的技术任务 / 例句语境，不是“这个单词只有技术义”。
2. 对 129 个精确四级交集，另外展示 ECDICT 的通用 / 其他释义；源文本中 `[计]` 后面的内容单独标为“计算机候选义 · ECDICT [计]”。不把整个词典释义都塞进“技术义”。
3. `address`、`image`、`instance`、`port`、`process`、`volume` 保留原始场景义，并列出冻结 metadata 给出的 Kubernetes / CNCF 技术语境链接。此链接不证明考试考查该技术义。
4. `host` 和 `thread` 是新增 **`ec-host-4740ae63` / `ec-thread-39200d1e`**，不是不存在的 `w-host` / `w-thread`。它们保留源通用义和 `[计]` 候选义，不因 `[计]` 就升级成已核实的现代技术场景。
5. 原有 `w-gpu` 保留图形处理器意义；源词典的 `gpu = ground power unit` 与本场景无关，**没有引入或覆盖**。
6. `w-runtime` 只获得已有技术词头对应的 cloud-native / programming 标签覆盖，不获得 `cet4`，也不凭空补音标。它的“本场景义”始终显示原 `word.meaning`；metadata 中后来补充的不同技术简释不替代、也不冒称为原创卡片原义。本次没有展示未独立附来源的补充文本。
7. 未识别的自备词条保留自身 `meaning`、`tags` 和 `source`，不因英文拼写看起来相关而获得第三方考试或技术证据。

`enrichWordForPlanning(word)` 是一次性的克隆，保留原 `id`、`source`、音标、词性及其他字段，并复制标签与场景数组。只有 seed 覆盖词的克隆释义被整理成“场景 → 通用 / 其他 → 原词典 `[计]` 候选”的带标签文本，先放场景义，避免模型输入截断时丢失当前任务语境。**该克隆不能回存为词库、学习进度或已固定的每日计划。**
